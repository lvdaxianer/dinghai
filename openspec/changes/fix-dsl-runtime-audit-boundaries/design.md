# Design

## Context

当前引擎通过服务端 `QueryContext` 传递身份和数据源上下文，执行器使用有界线程池执行 JDBC 适配器。测试应用已有 traceId 解析和安全响应，但没有统一 HTTP 完成日志；关系 DSL 已有字段白名单和参数绑定，却缺少字段类型一致性和独立参数规模上限。

## Goals / Non-Goals

**Goals:**

- 在 HTTP 入口建立单一 trace/MDC 生命周期，完成日志只记录受控摘要。
- 让错误响应稳定且安全，同时保留内部可诊断信息。
- 在类型化计划构建阶段拒绝参数类型、参数数量和 `IN` 数量越界。
- 通过可插拔任务装饰器传播执行上下文，不让公共 SPI 依赖具体日志实现。
- 用真实数据库 HTTP 测试验证返回行、数据域和逻辑删除结果。
- 让计划摘要/缓存键包含 DSL 结构但不包含绑定参数值，避免同形状统计元数据造成摘要碰撞。

**Non-Goals:**

- 不在公共仓库实现企业登录、服务 Token 白名单或企业用户中心。
- 不引入跨数据库 JOIN 或原始 SQL 能力。
- 不把 `dataSourceId` 扩展为动态请求路由；本变更明确其为服务端上下文标识。

## Decisions

- **HTTP 审计放在 Filter**：Filter 统一记录一次请求完成事件，Controller 不重复记录；异常处理器只负责安全错误响应和内部异常分类日志。
- **错误消息固定映射**：编译诊断保留安全路径信息；后端、扩展、注册和未预期异常使用固定对外消息，避免透传驱动文本。
- **上下文传播使用 SPI 装饰器**：核心引擎只依赖一个可选的任务装饰契约；Spring Boot 默认提供 MDC 实现，宿主可以替换而不让 core/spi 依赖 SLF4J。
- **参数边界属于关系 DSL**：`maxParameters` 和 `maxInItems` 放入关系计划限制，字段类型与客户端声明类型必须严格一致；扩展约束继续由重写器做同样校验。
- **计划摘要使用安全结构材料**：通用 `ExecutionPlan` 默认使用元数据，关系计划额外提供不含参数值的 AST 结构；摘要仍只用于审计和缓存标识，不把 SQL 或绑定值暴露给接口。
- **真实测试检查业务结果**：脚本不只检查 `code=OK`，还检查目标日期、资产名、行数和不存在的其他域数据，避免空结果误报成功。

## Risks / Trade-offs

- [日志格式依赖宿主日志实现] → 公共引擎只输出安全摘要并提供装饰器；Spring Boot 测试应用用 MDC 验证上下文，企业应用可接入自己的日志桥。
- [严格类型校验可能拒绝历史宽松请求] → 这是有意的安全收紧，文档明确逻辑类型必须与白名单列类型一致；需要转换时由 DSL/Schema 显式扩展。
- [真实数据库测试依赖 Docker] → 脚本保留明确的 daemon 不可用错误，并使用固定本地测试端口、卷和无生产凭据模板。
