## Context

文件存储同时支持 SDK 内部调用和 Web 端点调用。SDK 调用已处于应用内部信任边界，不应被 HTTP 限流器影响；Web 上传会消耗请求连接、磁盘和 provider 写入能力，必须要求凭证并限制并发。Web 读取允许匿名浏览器访问，但仍会消耗 Web 执行器、provider 连接或本地文件传输资源，因此需要组件提供可配置的读取并发保护。

零拷贝变更为 Local 文件和远程缓存文件增加了 Tomcat sendfile 路径。原有读取信号量位于 `StreamingResponseBody` 的复制回调中，若继续放置在那里，sendfile 将绕过限制。因此许可必须在读取传输路径选择前获取，并由所有完成、异常和客户端断连路径释放。

## Goals / Non-Goals

**Goals:**

- 为 Web 上传增加独立、可配置的最大并发限制。
- 保留并强化 Web 读取最大并发限制，覆盖流式回退、缓存文件和零拷贝路径。
- 明确 Web 上传需要凭证，而 Web 读取不调用组件用户授权策略。
- 限流拒绝使用可识别的 429 响应并避免读取上传请求体。
- 保持 SDK 调用不经过 Web 限流，保持现有对象、缓存和 HTTP 语义。

**Non-Goals:**

- 首版不实现按 IP、用户、令牌的分布式令牌桶或滑动窗口。
- 首版不实现带宽整形、每日配额或总字节数限流。
- 不修改零拷贝传输的容器适配策略，只为其接入统一读取许可。
- 不改变 provider 原生凭证、稳定 ID 密码学格式或 SDK 合约。

## Decisions

1. **两套独立并发许可**：新增上传许可，与现有读取许可分离，避免大文件上传阻塞读取。使用非阻塞获取；达到上限立即返回 429，不在组件内部排队。
2. **入口处获取读取许可**：在读取元数据/选择本地文件或 provider 流之后、创建响应前建立一次传输许可，并将许可生命周期绑定到响应完成回调或流式回调。零拷贝注册成功与流式回退都必须持有同一许可。
3. **读取免组件凭证、上传保留凭证**：稳定 ID 和真实 key 的 Web 读取不调用 `FileStorageAccessPolicy`；上传仍验证预签名或直接访问授权。真实 key 公开暴露的风险由宿主路由/WAF承担，组件只提供可配置并发保护。
4. **统一 429 错误映射**：限流器返回结构化异常，由 Web 异常处理器映射为 429 和 `Retry-After`。拒绝发生在上传体读取之前；许可释放采用 `try/finally` 或响应完成回调保证异常安全。
5. **配置兼容**：保留 `web.max-concurrent-reads` 默认值 128，新增 `web.max-concurrent-uploads` 默认值 16；两者必须为正数。

## Risks / Trade-offs

- [匿名读取仍可被恶意请求消耗资源] → 使用可配置并发上限，并要求部署方在网关/WAF配置身份、IP或带宽策略。
- [sendfile 完成回调缺失导致许可长期占用] → 集成测试覆盖正常完成、注册失败和异常回退。
- [上传被拒绝后请求体仍由容器处理] → 在 Controller 入口限流并立即返回，配置请求体大小和连接超时作为宿主侧补充保护。

## Migration Plan

1. 等待零拷贝任务合并到集成分支，确认本地文件、缓存文件和流式路径均可识别。
2. 先以失败测试锁定上传/读取 429、匿名读取和许可释放行为。
3. 增加配置属性、限流组件和异常映射，再接入 Controller 的上传与全部读取路径。
4. 更新中英文配置文档并运行回归测试；若容器兼容性异常，可关闭零拷贝而保留读取限流。

## Open Questions
