# Spec Delta

## Purpose

为文件存储提供可选的、可恢复的异步对象删除能力，使删除请求能够快速登记并由后台可靠执行，同时保持未启用异步能力时既有同步删除行为不变。

## ADDED Requirements

### Requirement: 异步删除能力可选

文件存储组件 SHALL 默认使用同步删除；只有显式启用异步删除并提供有效任务存储配置时，组件才 SHALL 创建异步删除运行时。未配置任务存储时，应用 MUST NOT 因缺少 JDBC 配置启动失败。

#### Scenario: 未配置异步删除
- **WHEN** 应用未启用异步删除或未提供任务数据库配置
- **THEN** 既有 `FileStorage.delete` 可正常同步删除对象，且应用正常启动

#### Scenario: 显式启用但配置缺失
- **WHEN** 应用显式启用异步删除但任务数据库配置不完整
- **THEN** 应用在启动阶段以稳定配置错误失败，而不是静默回退为异步或丢弃任务

### Requirement: 删除任务登记与状态查询

组件 SHALL 提供异步删除任务提交和状态查询能力。提交成功 MUST 先持久化任务再返回稳定任务标识；任务 SHALL 至少支持 `PENDING`、`RUNNING`、`RETRY_WAIT`、`SUCCESS` 和 `FAILED` 状态。

#### Scenario: 成功登记异步删除
- **WHEN** 调用方提交合法的 storage alias 和 object key，且任务记录成功提交
- **THEN** 组件返回稳定 task id，任务状态为 `PENDING` 或已开始执行的 `RUNNING`，且服务重启后任务仍可被发现

#### Scenario: 重复提交同一请求
- **WHEN** 调用方使用同一幂等请求标识重复提交删除任务
- **THEN** 组件返回原任务标识，不创建重复的有效删除任务

#### Scenario: 查询不存在任务
- **WHEN** 调用方查询不存在或不属于当前授权范围的 task id
- **THEN** 组件返回稳定的任务不存在或无权访问错误，不泄露对象 key 或内部数据库信息

### Requirement: 删除任务最终一致且可重试

后台执行 SHALL 在任务被可靠抢占后调用当前 `FileStorage` provider 删除对象。对象已经不存在 SHALL 被视为删除目标已达成并标记 `SUCCESS`；可恢复失败 SHALL 按有限次数和退避策略进入 `RETRY_WAIT`，超过上限后标记 `FAILED` 并保留安全失败原因。

#### Scenario: 删除成功后标记完成
- **WHEN** provider 确认对象删除成功或确认对象不存在
- **THEN** 任务状态变为 `SUCCESS`，并记录完成时间

#### Scenario: 删除调用超时后安全重试
- **WHEN** provider 调用超时且无法确认对象是否已经删除
- **THEN** 任务进入有限重试流程，重复删除不会造成额外业务副作用

#### Scenario: 超过最大重试次数
- **WHEN** 任务连续失败并达到配置的最大重试次数
- **THEN** 任务变为 `FAILED`，保留可诊断但不包含密钥、完整路径或文件内容的错误信息

### Requirement: 单机和高可用任务存储

组件 SHALL 支持使用本地 SQLite 文件保存单机任务，也 SHALL 支持使用宿主提供的关系型数据库连接支持多实例部署。多个 worker 同时运行时，同一任务 MUST 只有一个有效租约持有者；租约过期后任务 SHALL 可被其他实例接管。

#### Scenario: SQLite 单机恢复
- **WHEN** 单机模式使用 SQLite 登记任务后应用进程在执行前退出并重新启动
- **THEN** 新进程能够扫描并继续执行未完成任务，任务记录不会因进程退出丢失

#### Scenario: 多实例竞争任务
- **WHEN** 多个应用实例同时扫描同一待执行任务
- **THEN** 只有成功获得租约的实例执行该任务，其他实例不得将其重复标记为成功

#### Scenario: worker 租约过期
- **WHEN** 持有任务租约的实例在删除期间宕机且租约过期
- **THEN** 其他实例能够重新获得该任务并继续执行，旧实例不能覆盖新实例的最终状态

### Requirement: 删除执行资源隔离

异步删除 SHALL 使用独立、有界的业务执行资源，并配置有限队列、明确拒绝行为和可配置并发上限。删除任务不得占用文件存储 Web 读取执行器来执行后台删除。

#### Scenario: 删除队列达到容量
- **WHEN** 删除 worker 的有界队列已满
- **THEN** 新任务保留在持久化任务表中并由后续轮询处理，系统不得无限创建线程或静默丢弃已登记任务

#### Scenario: 删除执行与读取隔离
- **WHEN** 后台删除任务持续调用本地文件系统或远端 provider
- **THEN** 删除任务的阻塞操作不会耗尽文件存储 Web 读取执行器
